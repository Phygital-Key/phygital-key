How it works

Four roles. One signed yes.

Each role has its own authority. None of them can do another's job.

01The agentAsks for one exact request, for one service.MCP · A2A
02The gateShows every field. Has no key, so it can never approve.approval page
03YouApprove with your fingerprint, face, PIN or key.ES256 signature
04The serviceChecks the signed yes itself, offline, then acts.verify() → ok

The agent's tools

Six tools.
None can approve.

The agent can ask, wait, cancel, use a standing approval and pass back a receipt. Only your key signs.

request_approvalAsk for one exact request, for one service
get_approvalWait for your answer and get the signed yes
cancel_approvalWithdraw a request, or revoke a standing one
request_standing_approvalAsk for a limited, repeated permission
use_standing_approvalA one-minute use token, inside the limits
record_receiptPass back the service's signed "done"
